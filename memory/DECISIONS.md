# DECISIONS — журнал решений

Формат — `PROTOCOL.md`, §4.2. Решения не удаляются, только помечаются `отменено` со ссылкой на замену.

Ранние решения по устройству самого протокола (регулятор (раздел 2), форма изложения (раздел 8), архитектура (раздел 9), приоритет практики (раздел 10), учёт (раздел 11)) не дублируются здесь — они зафиксированы прямо в `PROTOCOL.md` и в датированных записях `CALIBRATION.md`/`ERRORS.md` (§4.5: файлы проекта — источник истины, дублирование запрещено). Здесь — решения, которые не принадлежат целиком ни одному другому файлу.

## D-001 · Память проекта — отдельная папка `memory/` · 2026-09-29
Решение:    файлы `CALIBRATION.md`, `READER.md`, `ERRORS.md`, `ARCHITECTURES.md`, `STATE.md`, `DECISIONS.md`, `GLOSSARY.md`, `OPEN_QUESTIONS.md` хранятся в `memory/`; `PROTOCOL.md` и `check_answer.py` — в корне.
Почему:     отделяет память протокола от содержательных материалов проекта; альтернатива (всё в корне) была проще, но пользователь выбрал разделение.
Статус:     принято
Влияет на:  все пути в `PROTOCOL.md`, ссылки в файлах памяти между собой

## D-002 · Версионность протокола — через git · 2026-09-29
Решение:    папка становится git-репозиторием; изменения `PROTOCOL.md` и файлов памяти коммитятся вместо номера версии в тексте.
Почему:     стандартный инструмент, полная история бесплатно; альтернативы (номер версии + список правок в файле, либо вообще без версионности — журнал `CALIBRATION.md`/`ERRORS.md` и так фиксирует изменения) пользователь не выбрал.
Статус:     принято
Влияет на:  весь `protocol_AI/` становится git-репозиторием

## D-003 · Быстрый режим для служебных реплик · 2026-09-29
Решение:    реплики без нового факта/определения/вывода (подтверждения, статусы, уточняющие вопросы) не требуют полной дисциплины Ф.1–Ф.5; ссылки вперёд и отчёт о токенах обязательны всегда. Правило — `PROTOCOL.md`, Ф.6.
Почему:     полная форма Ф на каждую короткую реплику избыточна и утомительна; альтернатива (единые правила всегда) пользователь не выбрал.
Статус:     принято
Влияет на:  Ф.6

Поручение включает визуальное представление всех правил и памяти, предложения по диалектическим требованиям и стенды проверки; разрешено использовать подключения ИИ из соседних проектов.
Почему:     пользователь запросил обозримую систему и проверку улучшений памяти, одобрил начало работы и явно обозначил момент смены модели.
Статус:     принято пользователем в чате. Конкретные новые правила сжатия и изменения C/D ещё не утверждены этим решением.
Влияет на:  архитектура `docs/ARCHITECTURE.md`, задание `docs/UI_HANDOFF.md`, лаборатория `docs/EXPERIMENT_MEMORY.md`, текущее состояние проекта

## D-008 · Продолжить рекомендации точной памяти · 2026-09-30
Решение:    по поручению пользователя «ок продолжай» реализовать рекомендации после дополнительных сравнений и проверить их на длинных историях. Выполнены диагностика нужды, точный контекст, проверка ответов, два длинных сравнения и две проверки исправленной версии.
Почему:     найденные ошибки ссылок, статусов, областей и лишних процедур требовали конкретных средств сохранения и контроля, а короткие случаи не проверяли длинную историю.
Статус:     рабочее поручение выполнено. Новая схема допускает неизвестность null; 20 вызовов, 90 008 API-токенов, 61 тест. Техническая проверка не утверждает смысловую истинность или глобальное изменение протокола; оценки пользователя не присваивались.
Влияет на:  protocol_atlas/context.py, память, лабораторию, интерфейс, docs/EXACT_MEMORY_RESULTS.md. История не переписывается, математический пилот остаётся приостановленным. Новые серии автоматически не запускаются.
