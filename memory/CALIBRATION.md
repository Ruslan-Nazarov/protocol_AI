## Наблюдения о «плохих кусках»

Сюда — эмпирические выводы из журнала: какие сочетания факторов V/L/H/N реально ломают ИИ, где оценка нагрузки расходится с фактом. Именно это уточняет карту кусков (К.2).

- Проверка кодом (A) не ловит нарушения понятности: ответ, верный по числам, может быть непонятен. Для Ф нужна проверка B (читатель) после каждой порции.
- Правило К.6 режет C вдвое одинаково для ошибок разной тяжести (пропущенное определение и ошибка в выводе). Две стилистические ошибки подряд довели C с 4 до 1. Возможно, срез должен зависеть от тяжести. Предложить пользователю пересмотреть.
- Фактор N (неявность) надо оценивать по `READER.md`: каждый термин, которого там нет, повышает N. В пилоте N была бы 3, а не 2.
- Пилот «объяснение темы» приостановлен на C=1, D=0 — самых жёстких значениях. Следующая калибровка идёт на другой ситуации (не математика/Риман), выбор задачи — 2026-09-29.
