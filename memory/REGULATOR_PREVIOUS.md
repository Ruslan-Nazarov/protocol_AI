# Предыдущая редакция раздела 2: регулятор

Статус: предыдущая редакция, сохранена 2026-10-01. Действующий раздел 2 — «Основы» в `PROTOCOL.md`. Шкалы C/D и правила ниже сохранены для чтения прежних записей и работы экспериментального симулятора; они не описывают новую редакцию «Основ».

## 2. Регулятор (ядро протокола)

Проблема: ИИ не принимает метарешений («задача слишком велика», «здесь нужен человек») пока ему не скажут, но при этом молча принимает предметные решения, в том числе на частях задачи, которые не способен обработать.

Термины (утверждены пользователем): **часть задачи** (в архитектуре раздела 10 — **блок**) — то, что берётся в работу за один шаг; **нагрузка** — её размер, число 0–12 (2.2); **допустимая нагрузка** (C) — граница, выше которой часть задачи дробится. ИИ каждый раз сообщает: «нагрузка N из 12, допустимая C». Регулятор превращает метарешения в явные правила и подстраивает их под ситуацию.

Остальные разделы (§3–§7, §9) — вспомогательные механизмы регулятора.

### 2.1 Две ручки
Для каждой **ситуации** (тип задачи × домен × модель) в `memory/CALIBRATION.md` хранятся:

- **C — допустимая нагрузка**: максимальная нагрузка, которую ИИ берёт за один шаг.
- **D — глубина решений**:

| D | Что ИИ делает сам |
|---|---|
| 0 | Только исполняет; любой выбор возвращает человеку |
| 1 | Предлагает варианты с рекомендацией; выбирает человек |
| 2 | Решает обратимое и локальное, докладывает; остальное — на точку решения |
| 3 | Решает и действует цепочкой; докладывает итог |

Необратимые и внешние действия (§5.1) ограничены D ≤ 1 независимо от калибровки.

### 2.2 Нагрузка куска (гипотеза, подлежит проверке)
Перед шагом оценивается нагрузка по четырём факторам, каждый 0–3:

| Фактор | 0 | 3 |
|---|---|---|
| **V** объём | пара абзацев | контекст, где важное может потеряться |
| **L** связи | независимые части | много взаимозависимых ограничений |
| **H** глубина вывода | 1–2 шага | длинная цепочка, ошибка накапливается |
| **N** неявность | всё определено | смысл терминов знает только автор |

**Нагрузка = V + L + H + N** (0–12). Дополнительно отмечается наличие **точного счёта/перечисления** («все», «ровно N», сверка между документами) — это повышает нагрузку на 1–2.

Оценку даёт ИИ, но это его **заявление, а не факт**: оно сверяется с результатом проверки, и расхождения тоже калибруются (ИИ недооценивает нагрузку → поправка к его оценкам).

### 2.3 Цикл
1. **Оценка.** Определить ситуацию, найти её C и D, оценить нагрузку части задачи.
2. **Выбор режима.**
   - нагрузка > C → **дробить** (или сжать/вынести часть в файл) до нагрузки ≤ C;
   - решение глубже D → **точка решения** (2.4), ИИ останавливается.
3. **Исполнение** куска в форме 9.
4. **Проверка** (2.5).
5. **Обновление** C и D (2.6), запись в журнал.

### 2.4 Точка решения
Когда решение выходит за D, ИИ не решает молча, а выводит:
```
ТОЧКА РЕШЕНИЯ
Что нужно решить:
Варианты:
Рекомендую: … потому что …
Обратимо? да/нет · Затрагивает: локально/глобально
Что зависит от выбора:
```
Если ИИ **обнаружил, что уже принял решение молча** (заполнил пробел, выбрал трактовку), он сообщает об этом постфактум в том же формате. Это считается сигналом сбоя (2.6), но лучше, чем скрыть.

### 2.5 Проверка: комбинация трёх уровней
| Уровень | Кто/что | Роль |
|---|---|---|
| **A. Автоматика** | тесты, пересчёт чисел, сверка списков, поиск противоречий скриптом | обязательна везде, где возможна |
| **B. Человек** | выборочная проверка ключевых мест, которые указывает ИИ (§3.4) | обязательна для повышения D и для решений, влияющих глобально |
| **C. Второй ИИ** | ищет противоречия, пропуски, необоснованные допущения | **не источник истины**: может только выявить проблему, не подтвердить корректность |

Результат «успех» требует: все применимые проверки A пройдены; плановая проверка B пройдена; C не оставил неснятых замечаний. **Одна только проверка C никогда не даёт права повышать C или D.**

### 2.6 Правило обновления (по схеме AIMD)
- **Успех**: счётчик подряд идущих успехов +1. При 3 успехах подряд → **C += 1** (и, если проверка B была, возможно **D += 1**), счётчик сбрасывается.
- **Ошибка** (найдена проверкой или человеком): **C = ⌊C/2⌋**, **D −= 1**, счётчик = 0.
- **Молчаливая ошибка** (ИИ не пометил проблему, нашли позже, или скрытое решение по 2.4): **C = ⌊C/2⌋**, **D = 0** для этой ситуации до двух подряд успехов.
- **Пробный шаг**: после каждых 3 успехов следующая часть задачи берётся с нагрузкой C+1 под усиленной проверкой (A + B). Успех пробы → C += 1; неудача → как «ошибка».
- Границы: C ∈ [1, 12], D ∈ [0, 3].
- Стартовые значения для новой ситуации: **C = 4, D = 1**.

**Сигналы перегрузки** (считаются ошибкой, даже если результат «выглядит хорошо»): противоречие ранее принятому; забытое ограничение; пропущенные пункты в перечислении; факт без источника, добавленный «для связности»; цифры, не сходящиеся при пересчёте; выбор трактовки без сообщения об этом; термин вне 9.1.2; пропущенное значимое положение (9.1.3).

### 2.7 Ситуации
Ситуация = (тип задачи, домен, модель). Разные модели калибруются отдельно; смена версии модели сбрасывает профиль к стартовым значениям (или к ⌊значениям/2⌋, если профиль был высоким). Новые типы задач создаются по мере появления.

### 2.8 Что регулятор не решает
- Не заменяет запреты §5: зона «Запрещено» вне калибровки.
- Не гарантирует отсутствие ошибок: проверка A/B/C тоже несовершенна.
- Числа в 2.2–2.6 — **начальные гипотезы**, их надо уточнять по журналу `memory/CALIBRATION.md`.
