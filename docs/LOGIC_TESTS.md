# Проверка системы без лишних вызовов модели

## Короткий прогон

```powershell
python -X utf8 scripts/verify_logic_core.py --quick
```

Восемь небольших тестов проверяют правильный вывод, общее условие соответствия ожидаемому символу и девять других демонстрационных мутаций, отсутствие ложного запрета G в цитате или в роли другого понятия, второй логический профиль, запрет завершения без проверки, приоритет последующего отказа, повторную проверку импорта и запрет обхода через свободный ответ модели. Ответ модели в интеграционном тесте подставляется локально; обращения к API нет.

Проверка символа содержит 66 сочетаний: два ожидаемых обозначения (S и T), для каждого — 26 заглавных латинских букв и семь дополнительных вариантов (регистр, похожая буква другого алфавита, пробелы, повтор, составное имя, пустая строка). Два точных совпадения допускаются, остальные 64 отклоняются. Подстановка M или P проверяет неверное употребление уже разрешённого символа. Это конечные примеры для проверки общего сравнения, а не исчерпывающий перечень возможных нарушений.

Успех выводится одной строкой JSON: исход, число тестов, время, `model_calls: 0`, `api_tokens: 0`. При ошибке добавляется только диагностический отчёт. Это нулевой расход токенов API тестами; чтение отчёта в рабочем чате само имеет обычную стоимость контекста.

## Когда нужен более широкий прогон

После изменения ядра, адаптера или допуска:

```powershell
python -X utf8 scripts/verify_logic_core.py
```

Дополнительно проверяются версии, позднее отклонение в цепочке, восстановление, ограничения входа, сохранение истинности правил на всех небольших моделях и установка движка. Полная регрессия проекта выполняется перед завершением связанной редакции:

```powershell
python -X utf8 scripts/verify_logic_revision.py --tests
```

Положительные примеры обязаны проходить, отрицательные — отклоняться. Замена проверки функцией «всегда успех» нарушит отрицательные тесты; «всегда отказ» нарушит положительные. Намеренное изменение ошибки не является наблюдаемым сбоем живой модели.

Для осмотра примеров отдельно: `python scripts/run_logic_demo.py --output build/logic_demo.json`. Отчёт содержит закреплённый договор, исходные кандидаты и отказы.

Этого достаточно для первого технического испытания механизма. Оценка поведения живой модели — отдельная серия с бюджетом, повторениями и сравнением; она не запускается этими командами и не требуется для проверки соответствия зафиксированного кандидата установленному условию. Правильность выделения самого условия из человеческого задания рассматривается отдельно.
