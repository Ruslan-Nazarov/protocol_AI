# Первый живой прогон: наблюдения и ограничения

Дата: 2026-09-30. Сервис: Cerebras. Модель: `gpt-oss-120b`. Прогон: `935efd25ffd44f7c92751d89942c3be7`.

Этот документ — разбор разработчика по сохранённым ответам, не оценка человека и не доказательство превосходства метода. В интерфейсе смысл ответов остаётся «не проверено». Одна запись с таким статусом и точной цитатой сохранена для проверки формы оценки.

## Что выполнено

Один повтор, одинаковые модель и исходный эпизод; предельный размер обоих кратких вариантов — 12 000 символов. Выполнены два сжатия и три продолжения без чтения источников по ссылкам. Интервал между вызовами — 60 секунд; время всего прогона — 251,7 секунды, включая паузы.

| Условие | Размер переданного контекста | Проверка формата и заданий | Проверка указанных путей |
|---|---:|---|---|
| Полный материал | 31 448 символов | Пройдена | Пройдена |
| Обычное резюме | 8 175 символов | Пройдена | Не пройдена |
| Структура и основания | 6 989 символов | Пройдена | Пройдена |

Все пять вызовов вернули usage. По данным сервиса суммарно: 36 250 входных и 10 795 выходных токенов, включая сжатие. Стоимость в валюте неизвестна. Проверка путей устанавливает только то, что указанные пути принадлежат снимку; она не доказывает, что утверждение следует из источника.

## Наблюдения по содержанию

1. Обычное резюме передаёт часть ссылок без папки `memory/`, а продолжение ссылается и на `L.1` как на путь файла. Это обнаружила проверка точных путей.
2. В обычном варианте продолжение утверждает: «Если скрипт не нашёл замечаний, значит ответ удовлетворяет всем текущим правилам F.1.*». Это шире возможностей эвристического скрипта и противоречит описанным ограничениям.
3. В обоих кратких вариантах утрачено различие измеренного расхода и оценки. Обычный ответ предлагает `Tokens used: 1234` без usage и называет отчёт измеренным. Структурированный предлагает `total_tokens: 1234 [ГИПОТЕЗА]`, затем утверждает, что вручную добавленная строка обеспечивает реальный расход. `docs/LAB_CONTRACT.md` в снимке прямо требует неизвестного измеренного расхода без usage.
4. В структурированном варианте появление скрипта объяснено E-008, хотя журнал связывает введение механизма с повтором E-001 → E-002. Позднее расширение проверки смешано с причиной её появления.
5. Структурированный вариант предлагает разработать машиночитаемый протокол и автоматический регулятор как следующие шаги. В состоянии проекта исполнение регулятора отложено до решения неоднозначностей. Это требует отдельной оценки сохранения действующих решений.
6. Контроль с полным материалом тоже не безупречен: в задании об утраченном полном ответе он пересказывает описание ошибки и ставит `uncertainties: "Нет"`. Наличие подробного журнала не означает наличие полной стенограммы.

Цитаты в пунктах сокращены для чтения; точные ответы, сообщения и версии источников находятся в JSON прогона. Для принятия содержательной оценки человеком интерфейс требует точную цитату из полного ответа.

## Технические исходы подготовки

Прежние попытки сохранены отдельно. Groq сначала вернул HTTP 403; явный User-Agent исправил доступ. Затем Groq отклонил объём эпизода с HTTP 413. Cerebras без интервала выполнил два сжатия, после чего вернул HTTP 429. Опыт с интервалом и пределом 6000 символов завершился, но оба кратких текста превысили предел, поэтому продолжение для них не выполнялось. Ничего не обрезалось и не повторялось автоматически.

В ранней версии вопрос о расходе был неоднозначен: Л.1 допускает обозначенную оценку ИИ. Для последнего прогона вопрос уточнён до **измеренного расхода лаборатории**, а отдельный контракт включён в материал всех условий. Ранний и уточнённый сценарии не сравниваются как одинаковые.

## Следующая проверяемая гипотеза

Одной инструкции «сохрани основания» недостаточно для гарантии. Следующий механизм следует проверять как сохранение отдельных решений с точными цитатами, статусами, условиями и версиями, плюс восстановление источников по необходимости. Требуются независимые эпизоды: изменение основания, исключение и конфликт версий. Цель — проверить сохранение необходимости перехода и границ вывода; наличие названных полей или меньшая длина текста этого не доказывает.
